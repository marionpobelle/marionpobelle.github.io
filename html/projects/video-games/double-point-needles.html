OVERVIEW

How do you get proper rest when your inner voice urges you to work, plan, and anticipate?

This was the question that drove the creative process behind our submission for the Women Game Jam 2026, follwing the theme of learning to say no.

I worked with Marine Mousset (2D Artist & UI/UX Designer) and Maureen Bastian (Game & Narrative designer) to create this cozy narrative puzzle game, which explores the challenge of sitting down to knit when your mind is flooded with thoughts and to-do lists. Our approach to the theme is the notion of one's personal tyrant: the quiet voice full of guilt, anxiety, and injunctions that exhausts you when you are simply trying to relax. Resting, calming the mind and the thought spirals is often way easier said than done: how can you relax when you're always battling against yourself in silence?

My duties included:

  • Develop gameplay features (puzzles, interactions, dialogues, scarf coloring…)
  • UI implementation (main menu, puzzles, dialogues, end screen…)
  • Asset integration (2D sprites, animations, music and SFX…)
  • Collaborating closely with the team to ensure the development follows the design and the game can be easily fine-tuned and balanced
  • Maintain a feature list with regular updates so that everyone can track progress
  • And more!

YARNSPINNER

YarnSpinner is a great tool that facilitates the seamless implementation of narration in a game. I had been wanting to try it for a very long time and this was the perfect opportunity!

YarnSpinner includes a pre-made object that is the point of contact for both UI and code called the Dialogue System. This object contains the UI for the dialogue but, is also the bridge between the content of the Yarn project (nodes, variables, text, choices...) and the Unity project's code. Each dialogue option has a string type variable attached to it that corresponds to an enum's values and that influences the color of the knitting wool and that was communicated to the code through the Dialogue System, from narration to gameplay.

I had only 2 days to learn and work with YarnSpinner for this game jam but, I'll definitely tinker with it some more! It has a solid basic documentation and I'd love to explore the UI customization's limits.

PUZZLES

The kind of puzzle used in Double Point Needles is very common but I never implemented anything like this before. I had to think of a structure that wouldn't be too daunting to implement as I was short on time but that would also be easy to adapt to different sizes of puzzles.

The puzzle system is made out of 3 elements:

  • A Scriptable Object used to set up the puzzles. It contains lists of enum values for each line of the puzzle, with the enum values 'Start', 'End', 'Target' and 'Empty'.
  • A Point Prefab, that is aware of its state (start, end, target, empty) as well as of the points and lines surrounding it. Its sprite depends on its state.
  • The puzzle UI itself contains a Point Holder that gathers lines of points and a Line Holder that regroups all the puzzle lines, sorted vertically and horizontally.

The position of the player is initialized to the starting point of the puzzle and then updated as the game registers inputs. When pressing a puzzle input (arrow left, up, right, down), the puzzle checks the current player position point for neighbors in the direction that was pressed and animates the player position and the lines and updates the player position accordingly.

Each Point Prefab has an IsValid boolean. A puzzle is deemed completed when each point that is a Start, End or Target state has its IsValid boolean set to true and if the current player position is the Point Prefab with the End state.
